Una aplicación web sobre un servidor secuencial

Todo lo que ves —este HTML, la hoja de estilos, el script, las dos imágenes y las respuestas JSON— lo entrega un servidor Java escrito con ServerSocket que atiende una conexión a la vez.

Servicios del servidor

Cada botón hace una petición asíncrona con fetch. La página nunca se recarga: solo cambia el panel de resultado.

Resultado

Respuesta HTTP cruda de la última llamada 
Todavía no se ha llamado ningún servicio.

Errores controlados

Estos botones piden a propósito cosas que el servidor debe rechazar. El resultado aparece en el panel de error de arriba y en la pestaña Network del navegador.

El límite secuencial

GET /slow?seconds=N mantiene ocupado al único hilo del servidor durante N segundos. Abre esta página en dos ventanas: lanza la petición lenta en una y, sin esperar, pide la hora en la otra. La segunda ventana no recibe respuesta hasta que la primera termina.

La interfaz sigue respondiendo mientras esperas —puedes escribir y pulsar otros botones— porque el cliente es asíncrono. El servidor, en cambio, sigue siendo secuencial.

Recursos estáticos

Una sola página HTML genera varias peticiones HTTP: el documento, la hoja de estilos, el script y cada imagen viajan por separado, una detrás de otra.

  • /health — estado del proceso
  • /time — hora del servidor
  • /hello?name=Ana — saludo
  • /square?number=12 — cuadrado
  • /logo.png · /secuencial.jpg
